# Границы редакций Enterprise Control Center (Community vs Professional vs Enterprise)

Настоящий документ фиксирует технические границы между бесплатной базовой редакцией (**Community Edition**) и коммерческими редакциями (**Professional Edition**, **Enterprise Edition**), реализованные в модуле `server/licensing.ts`.

> **Правовое примечание:** технические ограничения и квоты не заменяют юридически оформленное лицензионное соглашение (см. `docs/licensing/LICENSING-STRATEGY.md` и `docs/licensing/COMMERCIAL-LICENSE-DRAFT.md`).

## 1. Сравнительная матрица редакций

| Возможность / Ограничение | Community Edition | Professional Edition | Enterprise Edition |
| --- | --- | --- | --- |
| Пользователи в организации | до `10` | до `100` *(или по лицензии)* | без лимита *(или по лицензии)* |
| Инвентарные активы (`assets`) | до `250` | до `2500` *(или по лицензии)* | без лимита *(или по лицензии)* |
| Лицензии ПО (`software_licenses`) | до `50` | до `500` *(или по лицензии)* | без лимита *(или по лицензии)* |
| Базовый учёт, RBAC, CSV, Аудит (`core_inventory`, `audit_export`) | Включено | Включено | Включено |
| SHA-256 бэкапы, снимки и DR-учения (`sha256_backups`, `recovery_drills`) | Включено | Включено | Включено |
| Отчётность SLA и операционного соответствия (`enterprise_sla_reporting`) | Недоступно (`403`) | Включено | Включено |
| Обезличенный пакет диагностики (`support_bundle_export`) | Недоступно (`403`) | Включено | Включено |
| Индивидуальная политика хранения (`custom_retention_policy`) | Недоступно | Включено | Включено |
| Выделенная поддержка (`dedicated_support`) | Недоступно | Недоступно | Включено |

## 2. Механизм офлайн-активации (`ECC1`)

Коммерческие функции активируются автономно без обращения к внешним облачным серверам:

- Формат ключа: `ECC1.<base64url-payload>.<hmac-sha256-signature>`
- Проверка подписи: выполняется функцией `verifyOfflineLicenseToken()` с использованием `crypto.timingSafeEqual` и выделенного ключа `ECC_LICENSE_SIGNING_KEY` (минимум 32 байта).
- Если `ECC_LICENSE_SIGNING_KEY` не настроен, активация коммерческих лицензий отклоняется с HTTP 503. Встроенного ключа по умолчанию нет: это исключает выпуск валидных коммерческих лицензий с использованием известного публичного секрета.
- Обязательные проверки при активации (`POST /api/v1/system/license/activate`):
  1. Корректная цифровая подпись `HMAC-SHA256`.
  2. Совпадение `organization_name` с текущей организацией (или явный `*`).
  3. Срок действия `expires_at` в будущем и позже `issued_at`.
  4. Корректность редакции (`professional` / `enterprise`) и числовых квот.
- При истечении срока действия `license_status` автоматически переходит в `expired`, а доступные функции и квоты откатываются до уровня `Community Edition` без удаления накопленных данных организации.

## 3. Приватность диагностического пакета (`support-bundle`)

Экспорт `GET /api/v1/enterprise/support-bundle` включает только агрегированную телеметрию, статус проверок готовности (`readiness_checks`), сводку DR/бэкапов и коды HTTP-ошибок (`>= 400`, исключая `401`). Пароли, `scrypt`-хеши, Bearer-токены, ключи подписи, email-адреса и пользовательские записи в пакет не включаются.
